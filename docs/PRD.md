## **1\. 简介与目标**

### **1.1 产品概述**

本产品是一款基于 **Chrome 扩展程序** 的桌面宠物应用，核心价值在于深度结合 Google API （**AI 文生图/图文生视频）** 能力和 **用户行为感知** 技术，为用户提供一个高度个性化和上下文感知的虚拟伙伴。

### **1.2 核心目标**

1. **实现形象定制：** 用户通过文本描述（Prompt）即可生成独特的宠物形象及其动态 GIF 动作。  
2. **增强互动性：** 宠物能够感知用户当前的浏览内容（例如从学习切换到娱乐），并据此**自动切换形态和动作**，提供沉浸式的陪伴体验。

## **4\. 技术实现与模型选型**

### **4.1 扩展程序架构**

| 组件 | 作用 | 核心 API/技术 |
| :---- | :---- | :---- |
| **背景脚本 (Service Worker)** | 负责监听页面切换、内容分类、安全调用后端 API。是扩展程序的大脑。 | chrome.tabs.onUpdated, chrome.runtime.sendMessage |
| **内容脚本 (Content Script)** | （可选/视情况）注入到网页 DOM 中，用于获取页面更深层的内容（如文章摘要），辅助**F3**。 | DOM 操作，chrome.runtime.onMessage |
| **前端/UI 渲染** | 桌面宠物本体（浮动 DIV 或 Sidebar），负责 GIF 播放和形态切换。 | HTML/CSS/JavaScript |
| **API 后端服务** | （关键）负责接收扩展程序请求，**安全地**调用 AI 模型，并将 GIF 文件流或 URL 返回给扩展程序。 | Google Cloud Functions / AWS Lambda 等，用于保护 API Key。 |

### **4.2 AI 模型选型**

已初步验证谷歌的nano banana、AI视频功能可以实现快速、稳定、统一的宠物形象、动态生成。

| 功能 | 推荐模型/技术 | 考量因素 |
| :---- | :---- | :---- |
| **文生图/动图** | **Hotshot-XL \+ SDXL 生态** 或 **Google Gemini Nano Banana API** | Hotshot-XL 专精于 SDXL 生态的 **Text-to-GIF**，风格一致性高；Gemini 提供强大的多模态生成能力。 |
| **对话** | **Prompt API** | 无 |

### **4.3 权限要求（难点，happy dog没实现）**

为了实现上下文感知，必须申请以下关键权限：

JSON

"permissions": \[  
  "tabs",       // 允许监听和访问标签页信息  
  "\<all\_urls\>"  // 允许访问所有网站的 URL 和基本信息  
\],  
"host\_permissions": \[  
  "\*"           // 允许注入 Content Script (如果需要)  
\]

为了解决“**每次切换新网页都需要点击才出现宠物**”和“**实时形态跟随**”这两个核心痛点，需要关注以下技术点：

1. **权限设置优化：**  
   * **要求：** 在扩展程序安装时，明确要求并设置 **“在所有网站上自动运行”** 权限。这是解决“点击才出现”问题的**最直接**方法。  
   * **实现：** 确保 manifest.json 文件中的 content\_scripts 或 host\_permissions 设置正确。  
2. **跨窗口状态同步机制（核心技术难点）：**  
   * **问题：** 扩展程序在每个窗口/标签页都是**独立运行**的。  
   * **解决：** 需要利用浏览器的 **Background Service Worker** 或 **Background Page** 作为中央处理器。  
     * 当宠物状态发生变化（例如：从“走路”变为“睡觉”），**Content Script** (内容脚本) 会将该状态通过 **Messaging API** 发送到 **Background Service Worker**。  
     * **Background Service Worker** 存储最新状态，并向**所有其他激活的浏览器窗口/标签页**广播此**最新状态**。  
     * 新窗口或切换激活窗口时，**Content Script** 启动时立即向 **Background Service Worker** 请求**当前宠物的最新状态**并加载，实现**实时跟随和状态同步**。  
3. **性能优化：**  
   * 宠物形象和持续运行的代码可能占用资源。应确保在**非活动标签页**中，宠物相关的 **Content Script** 处于**低功耗/暂停**状态，仅在标签页切换为**活动状态**时才完全激活动画和互动逻辑。
